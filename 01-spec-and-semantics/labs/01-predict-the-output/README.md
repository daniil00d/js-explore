# Лаба 01-1. Предскажи результат

**Сложность:** для начала. **Что тренируем:** hoisting, TDZ, ASI, строгий режим.

## Задача

В [`cases.mjs`](./cases.mjs) четырнадцать фрагментов. Для каждого нужно, **не запуская
код**, предсказать, чем он закончится, и вписать ответ в [`answers.mjs`](./answers.mjs).

Правила записи ответа:

- фрагмент вычислился — пиши значение: `undefined`, `99`, `[3, 3, 3]`, `'вызвалась'`;
- фрагмент упал — пиши имя конструктора ошибки строкой: `'ReferenceError'`,
  `'TypeError'`, `'SyntaxError'`.

Сравнение строгое, с учётом типа. Строка `'undefined'`, которую вернул `typeof`,
и значение `undefined` — разные ответы, и в списке есть оба случая.

## Как проверить

```bash
node 01-spec-and-semantics/labs/01-predict-the-output/check.mjs
```

Проверка выполняет каждый фрагмент в чистом контексте через `node:vm` и сверяет
результат с твоим ответом. Пока ответ не сошёлся, правильное значение не
показывается — только его форма («число», «строка», «список из 3») и подсказка.

## Смысл упражнения

Все четырнадцать случаев — не головоломки ради головоломок. Это места, где
интуиция чаще всего расходится со спецификацией:

- объявление и присваивание — разные шаги, и поднимается только первый;
- `typeof` спасает от необъявленных имён, но не от TDZ;
- перенос строки иногда завершает инструкцию, а иногда наоборот склеивает две;
- строгий режим меняет не только запреты, но и значения (`this`, `arguments`);
- ранняя ошибка отменяет выполнение всего фрагмента, а не только сломанной строки.

Если ответ не сошёлся — это самое полезное место лабы. Сначала пойми, почему
движок сделал иначе, и только потом смотри разбор.
