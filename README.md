# js-explore

Учебный репозиторий про JavaScript с точки зрения **статического анализа и компиляции**:
что происходит с кодом от текста в файле до машинных инструкций, и что об этом коде можно
узнать, ни разу его не запустив.

Репозиторий устроен как маршрут: пронумерованные папки идут от «текста программы» к
«машинному коду и памяти». В каждой папке лежит `README.md` (что изучаем, вопросы для
самопроверки, ссылки) и `examples/` — туда постепенно складываем запускаемые примеры.

## Порядок изучения

Разделы можно читать подряд, но есть два относительно независимых трека:

- **Статический трек (01 → 07):** текст программы, AST, анализ без запуска, типы,
  трансформации и сборка. Здесь код — это данные, которые мы разбираем и переписываем.
- **Динамический трек (08 → 12):** что с этим кодом делает V8 в рантайме — байткод,
  обратная связь по типам, JIT, деоптимизация и память.

Разделы `00`, `13` и `14` — вспомогательные: инструменты, соседняя экосистема и измерения.

Смысл читать оба трека в том, что они встречаются посередине: статически известная форма
объектов и типы из TypeScript влияют (или, что важнее, **не** влияют) на то, какие
предположения V8 сделает в рантайме.

## Как устроена каждая папка

```
NN-topic/
  README.md     # зачем, что изучаем, вопросы для самопроверки, ссылки
  examples/     # запускаемые примеры (добавляем по ходу)
```

В `README.md` каждой папки есть раздел «Что положим в `examples/`» — это план примеров,
который наполняем по мере прохождения темы.

## Соглашения

- Примеры — на чистом Node.js без сборки, если тема не требует обратного.
- Каждый пример должен запускаться одной командой, а нужные флаги V8 указаны в шапке файла
  комментарием.
- Вывод движка (байткод, логи деоптимизации) не коммитим целиком: он огромный и зависит от
  версии V8. Вместо этого — команда для воспроизведения и короткая выжимка.
- Версия движка имеет значение: почти всё в разделах 08–12 менялось между релизами V8,
  поэтому в заметках фиксируем `node --version` / `d8 --version`.
