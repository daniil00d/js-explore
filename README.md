# js-explore

Учебный репозиторий про JavaScript с точки зрения **статического анализа и компиляции**:
что происходит с кодом от текста в файле до машинных инструкций, и что об этом коде можно
узнать, ни разу его не запустив.

Репозиторий устроен как маршрут: пронумерованные папки идут от «текста программы» к
«машинному коду и памяти». В каждой папке лежит `README.md` (что изучаем, вопросы для
самопроверки, ссылки) и `examples/` — туда постепенно складываем запускаемые примеры.
У наполненных разделов рядом появляется `labs/` — задачи с автоматической проверкой.

## Порядок изучения

Разделы можно читать подряд, но есть два относительно независимых трека:

- **Статический трек (01 → 07):** текст программы, AST, анализ без запуска, типы,
  трансформации и сборка. Здесь код — это данные, которые мы разбираем и переписываем.
- **Динамический трек (08 → 12):** что с этим кодом делает V8 в рантайме — байткод,
  обратная связь по типам, JIT, деоптимизация и память.

Разделы `00`, `13` и `14` — вспомогательные: инструменты, соседняя экосистема и измерения.

Смысл читать оба трека в том, что они встречаются посередине: статически известная форма
объектов и типы из TypeScript влияют (или, что важнее, **не** влияют) на то, какие
предположения V8 сделает в рантайме.

## Лабы

Примеры показывают, как всё устроено; лабы заставляют это сделать руками. Каждая
лаба — отдельная папка с заданием, заготовкой, проверкой и разбором:

```bash
node tools/labs.mjs                    # обзор: что сделано, что осталось
node tools/labs.mjs --solution         # прогнать все лабы на эталонных решениях
```

| Лаба | Задача |
| --- | --- |
| [00-setup/01-flag-detective](./00-setup/labs/01-flag-detective) | По логам V8 выяснить, что случилось с четырьмя функциями |
| [00-setup/02-pick-the-flags](./00-setup/labs/02-pick-the-flags) | Подобрать флаги, которые меняют поведение движка нужным образом |
| [01-spec-and-semantics/01-predict-the-output](./01-spec-and-semantics/labs/01-predict-the-output) | Предсказать результат четырнадцати фрагментов, не запуская их |
| [01-spec-and-semantics/02-implement-addition](./01-spec-and-semantics/labs/02-implement-addition) | Реализовать оператор `+` по абстрактным операциям ECMA-262 |
| [01-spec-and-semantics/03-module-order](./01-spec-and-semantics/labs/03-module-order) | Предсказать порядок инициализации в четырёх графах модулей |
| [02-lexing-parsing-ast/01-finish-the-lexer](./02-lexing-parsing-ast/labs/01-finish-the-lexer) | Дописать лексер: числа, приватные имена, «регулярка или деление» |
| [02-lexing-parsing-ast/02-write-a-lint-rule](./02-lexing-parsing-ast/labs/02-write-a-lint-rule) | Написать правило линтера `no-await-in-loop` на AST |
| [02-lexing-parsing-ast/03-surgical-codemod](./02-lexing-parsing-ast/labs/03-surgical-codemod) | Переписать вызовы, не изменив в файле ни одного лишнего байта |

Проверки устроены одинаково: правильных ответов в них нет. Правда каждый раз
добывается на месте — из логов V8, из настоящего оператора `+`, из лексера acorn,
из реально выполненного графа модулей. Поэтому лаба не рассыпается на другой версии
движка и её нельзя пройти, угадав формат ответа.

## Как устроена каждая папка

```
NN-topic/
  README.md     # зачем, что изучаем, вопросы для самопроверки, ссылки
  examples/     # запускаемые примеры (добавляем по ходу)
  labs/         # задачи с автопроверкой (в наполненных разделах)
```

В `README.md` каждой папки есть раздел «Что положим в `examples/`» — это план примеров,
который наполняем по мере прохождения темы. У наполненных разделов он заменён на
«Что лежит в `examples/`», а внутри `examples/` появляется свой `README.md` с порядком
чтения.

Рядом с разделами лежит `tools/` — общие помощники: печать таблиц и заголовков
(`format.mjs`), обвязка проверок для лаб (`lab.mjs`) и обзор всех лаб (`labs.mjs`).
В `package.json` — зависимости, которые нужны разделам про парсеры и трансформации.

## Соглашения

- Примеры — на чистом Node.js без сборки, если тема не требует обратного. Начиная
  с раздела 02 части примеров нужны парсеры из npm, поэтому перед запуском — `npm install`.
- Каждый пример должен запускаться одной командой, а нужные флаги V8 указаны в шапке файла
  комментарием.
- Вывод движка (байткод, логи деоптимизации) не коммитим целиком: он огромный и зависит от
  версии V8. Вместо этого — команда для воспроизведения и короткая выжимка.
- Версия движка имеет значение: почти всё в разделах 08–12 менялось между релизами V8,
  поэтому в заметках фиксируем `node --version` / `d8 --version`.
