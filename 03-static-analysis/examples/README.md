# Примеры: статический анализ

Раздел про то, что можно узнать о программе, не запуская её. Поэтому у каждого
примера есть вторая половина: вывод анализа сверяется с независимым источником —
с настоящим анализатором `eslint-scope`, с покрытием, которое собрал сам V8, с
результатом выполнения того же кода. Правильных ответов, вписанных в файл, здесь
нет.

Перед запуском:

```bash
npm install
```

Нужны `acorn`, `acorn-walk`, `eslint-scope` и пакеты Babel. Проверено на
`node v22.14.0 / V8 12.4`.

## Быстрый старт

```bash
node 03-static-analysis/examples/scope-analysis.mjs
node 03-static-analysis/examples/build-cfg.mjs
node 03-static-analysis/examples/dataflow.mjs
node 03-static-analysis/examples/ssa.mjs
node 03-static-analysis/examples/constant-folding.mjs
node 03-static-analysis/examples/call-graph.mjs
node 03-static-analysis/examples/analysis-killers.mjs
```

## В каком порядке читать

1. **`scope-analysis.mjs`** — самый практичный из примеров. Из одной таблицы
   привязок получаются `no-unused-vars`, `prefer-const` и безопасное
   переименование. Здесь же видно, почему минификатор работает с деревом, а не
   с текстом.
2. **`build-cfg.mjs`** — переход от дерева к графу. Главное здесь не сам граф, а
   разница между «недостижимо» и «не покрыто тестами»: она показана на покрытии,
   которое собрал сам движок.
3. **`dataflow.mjs`** вместе с [`dataflow-primer.md`](./dataflow-primer.md) —
   два анализа на одном графе, вперёд и назад. Отсюда становится понятно, что
   «переменная используется до присваивания» в TypeScript и распределение
   регистров в компиляторе — один и тот же алгоритм.
4. **`ssa.mjs`** — форма, в которой работают все настоящие компиляторы, включая
   TurboFan. Читать после `dataflow.mjs`: смысл SSA виден только по контрасту с
   тем, что приходится считать без неё.
5. **`constant-folding.mjs`** — абстрактная интерпретация на решётке из трёх
   уровней. Заодно ответ на вопрос, почему минификаторы не сворачивают всё, что
   могли бы: вычислить можно больше, чем записать литералом.
6. **`call-graph.mjs`** — первый пример, где анализ проигрывает с явным счётом:
   пять функций против десяти. Прямой пролог к разделам 07 и 10.
7. **`analysis-killers.mjs`** и [`limits-of-analysis.md`](./limits-of-analysis.md) —
   границы. Читать обязательно и лучше не в конце вечера: почти всё, что там
   ломает анализ, встречается в обычном рабочем коде.

## Как это устроено внутри

Три модуля переиспользуются примерами и стоит держать в голове их роли:

- [`scope.mjs`](./scope.mjs) — области видимости и разрешение имён. Всё
  остальное опирается на него, потому что без разрешения имён «переменная `total`»
  — это не переменная, а строка из семи букв.
- [`cfg.mjs`](./cfg.mjs) — граф потока управления, достижимость, доминаторы.
- [`variables.mjs`](./variables.mjs) — связка первых двух: какие переменные
  читает и пишет каждая инструкция графа.

Сверка с внешними источниками устроена так:

- `scope-analysis.mjs` сравнивает разрешение каждой ссылки с `eslint-scope` —
  тем же анализатором, на котором стоит ESLint;
- `build-cfg.mjs` запускает драйвер из `fixtures/` с `NODE_V8_COVERAGE` и
  читает, какие диапазоны движок ни разу не выполнил;
- `dataflow.mjs` и `constant-folding.mjs` выполняют разобранный текст через
  `new Function` и проверяют выводы на настоящих значениях;
- `call-graph.mjs` инструментирует модуль через Babel, исполняет его из
  `data:`-URL и сравнивает наблюдаемые рёбра со статическими.

Ничего не пишется в репозиторий: покрытие собирается во временный каталог и
удаляется, инструментированный код существует только в памяти.

## Что стоит попробовать самому

- В `cfg.mjs` уберите обработку литеральных условий (`staticTruthiness`) и
  посмотрите, что станет с примером про `while (true)`: `return null` после цикла
  внезапно окажется достижимым. Это самый короткий способ убедиться, что
  достижимость зависит от того, сколько анализ знает о значениях.
- В `dataflow.mjs` добавьте в подопытную функцию замыкание, которое меняет
  локальную переменную, и проверьте вывод про мёртвые записи. Он станет
  неверным — и это ровно то приближение, которое описано в
  [`limits-of-analysis.md`](./limits-of-analysis.md).
- В `constant-folding.mjs` замените `const debug = false` на параметр функции и
  посмотрите, как из вывода исчезнет половина подстановок. Точность анализа —
  это в основном вопрос того, сколько в коде констант.
- Прогоните `scope-analysis.mjs` на своём файле: подставьте `readFileSync`
  вместо строки `source`. Особенно интересно на файле с классами и приватными
  полями — там наша реализация областей видимости покажет свои пределы.
- Сравните вывод `build-cfg.mjs` с тем, что скажет ESLint с правилом
  `no-unreachable`, и с тем, что оставит от файла `esbuild --minify`.
