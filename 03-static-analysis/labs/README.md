# Лабы раздела 03

Три задачи по трём главным приёмам статического анализа: таблица имён, граф потока
управления, решётка значений.

| Лаба | Задача | Проверок |
| --- | --- | --- |
| [01-safe-rename](./01-safe-rename) | Переименовать переменную — или обоснованно отказаться | 20 |
| [02-eliminate-dead-code](./02-eliminate-dead-code) | Найти по графу код, до которого не доходит управление, и убрать его | 16 |
| [03-constant-propagation](./03-constant-propagation) | Выполнить функцию на описаниях значений вместо значений | 12 |

Порядок не случайный: каждая следующая знает о программе больше предыдущей. Первой
достаточно того, какое имя куда ведёт. Второй нужны пути между инструкциями. Третьей —
значения, которые по этим путям текут.

И у каждой есть вторая половина, из-за которой они и стоят в этом разделе: место, где
анализ обязан сдаться. В первой это `eval`, во второй — разница между «недостижимо» и
«не покрыто тестами», в третьей — замыкание, из-за которого `let count = 0` перестаёт
быть константой.

## Как это работает

```bash
npm install    # лабам нужны acorn и acorn-walk

node 03-static-analysis/labs/01-safe-rename/check.mjs
node 03-static-analysis/labs/01-safe-rename/check.mjs --solution
node tools/labs.mjs
```

Сам анализ писать не нужно — он берётся из примеров раздела: `examples/scope.mjs` для
первой лабы, `examples/cfg.mjs` для второй. Задача каждый раз в том, что делать с его
результатом, потому что именно там и живут ошибки.

Эталон для проверок не лежит в файле с ответами. Он добывается на месте:

- в лабе про переименование результат выполняется до и после правки, а по новому тексту
  заново строится дерево областей видимости — и сверяется, в какое объявление ведёт
  каждая ссылка;
- в лабе про мёртвый код фикстура запускается с `NODE_V8_COVERAGE`, и удалённые строки
  проверяются по покрытию, которое собрал сам движок;
- в лабе про константы фикстура вызывает свою функцию на нескольких наборах данных, и
  каждая названная константа сверяется с настоящим значением.

Все три сверки работают в одну сторону: они ловят ложные утверждения анализа, но не
подтверждают верные. Один запуск может опровергнуть утверждение обо всех запусках и не
может его доказать — поэтому вторым источником правды служит разметка в фикстурах.
