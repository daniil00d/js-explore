# Лаба 03-3. Распространение констант

**Сложность:** высокая. **Что тренируем:** абстрактную интерпретацию и решётку значений.

## Задача

Реализовать в [`propagate.mjs`](./propagate.mjs) функцию `analyze(source)`: выполнить
функцию не на значениях, а на их описаниях, и сказать про каждую переменную, известно ли
её значение на выходе.

```js
analyze(source);
// → [
//     { line: 4, name: 'base', value: '10' },
//     { line: 7, name: 'scaled', value: '⊤' },
//   ]
```

Одна запись на объявление верхнего уровня тела функции — по возрастанию строки. Значение
считается **на выходе из функции**, а не в точке объявления: важно последнее
присваивание, которое до выхода дожило. Печатает значение готовая `describe()`, её писать
не нужно.

## Решётка из трёх уровней

| Описание | Что означает |
| --- | --- |
| ничего (в `env` пусто) | до этой переменной анализ ещё не дошёл |
| константа | значение известно и одно и то же при любом запуске |
| `⊤` | может быть что угодно |

Главное правило: **`⊤` — всегда допустимый ответ**. Анализ, который на всё отвечает `⊤`,
бесполезен, но не неверен. А вот назвать константой то, что ей не является, нельзя ни при
каких обстоятельствах: на таком выводе минификатор подставит литерал, и программа
сломается. Отсюда следует, куда ошибаться, когда информации не хватает.

## Три места, где точность теряется

Это и есть содержание лабы — остальное механика.

**Слияние путей.** После `if` без известного условия обе ветки нужно объединить: одно
описание на переменную, а путей два. Одинаковые значения дают то же значение, разные —
`⊤`. Если же условие известно (`if (false)`), то вторая ветка в программе не участвует
вообще — ровно это делает минификатор с флагом `DEBUG`.

**Циклы.** Тело может выполниться ноль раз, один или миллион, и значения на каждом витке
свои. Простое и корректное приближение: всё, чему цикл присваивает, становится `⊤`.
Считать точнее можно, но это уже итерация до неподвижной точки — см.
[`dataflow-primer.md`](../../examples/dataflow-primer.md).

**Замыкания.** Если вложенная функция присваивает переменной, то момент присваивания
статически неизвестен: при вызове, в колбэке, через год из таймера. Единственный
корректный ответ — `⊤` с самого начала, ещё до того, как в тексте встретится хоть одно
использование. Проверьте на [`fixtures/closure.mjs`](./fixtures/closure.mjs): по тексту
`let count = 0` выглядит константой, и это неправда.

Сюда же относится всё, что мы не умеем считать: вызовы, обращения к полям, литералы
объектов. `obj.field` может оказаться геттером, вызов — вернуть что угодно, объект вообще
не записывается литералом. Ответ на всё это — `⊤`, и не из лени: см.
[`analysis-killers.mjs`](../../examples/analysis-killers.mjs).

## Как проверить

```bash
node 03-static-analysis/labs/03-constant-propagation/check.mjs
```

Ожидаемые значения помечены в фикстурах комментарием `// →`, а сверх этого каждая
названная константа проверяется запуском: фикстура вызывает свою функцию на нескольких
наборах данных и возвращает то, что получилось. Если анализ назвал значение константой, а
в каком-то запуске оно другое — это ошибка анализа, и никакие объяснения не помогут.

Обратное направление проверкой не наказывается: `⊤` на месте фактической константы —
потеря точности, а не ошибка. Именно поэтому есть ещё и разметка в фикстурах: без неё
лабу проходил бы анализ, который всегда отвечает `⊤`.

## Если застрял

<details>
<summary>Как устроено объединение описаний</summary>

```js
function merge(left, right) {
  if (left === undefined) return right;
  if (right === undefined) return left;
  if (left === TOP || right === TOP) return TOP;
  return Object.is(left.value, right.value) ? left : TOP;
}
```

`Object.is`, а не `===`: иначе `0` и `-0` склеятся в одно описание, а `NaN` перестанет
быть равным себе. Оба случая в реальной свёртке констант стреляют.
</details>

<details>
<summary>Как разобрать обе ветки if</summary>

Каждую — на своей копии окружения, а потом слить результаты:

```js
const thenEnv = new Map(env);
runStatement(node.consequent, thenEnv, context);
const elseEnv = new Map(env);
if (node.alternate) runStatement(node.alternate, elseEnv, context);
for (const name of new Set([...thenEnv.keys(), ...elseEnv.keys()])) {
  env.set(name, merge(thenEnv.get(name), elseEnv.get(name)));
}
```

Переменную, которой ни одна ветка не присваивала, слияние не портит: описание в обеих
копиях одно и то же.
</details>

<details>
<summary>Как найти имена, которые меняет замыкание</summary>

Сначала собрать вложенные функции обходом тела, потом в каждой — цели
`AssignmentExpression` и `UpdateExpression`. Дальше проще всего сделать так, чтобы запись
в такое имя ничего не меняла: `env.set(name, volatile.has(name) ? TOP : value)`. Тогда
объявление `let count = 0` само уложит туда `⊤`, и об этом не придётся помнить в каждой
ветке.
</details>

<details>
<summary>Почему циклу достаточно списка присваиваемых имён</summary>

Тело цикла для нашего приближения разбирать не нужно вовсе: что бы в нём ни считалось,
результат зависит от числа витков, а его мы не знаем. Достаточно узнать, каким именам
цикл присваивает, и поставить им `⊤`. Обход `walk.simple` по узлу цикла даёт этот список
сразу, включая вложенные блоки.
</details>

## Критерий готовности

`12 из 12`.

## Что здесь упрощено

Мы разбираем только тело функции, поэтому константы уровня модуля до анализа не доходят:
`const LIMIT = 3` рядом с функцией даёт `⊤` внутри неё. Настоящий анализатор ведёт
окружение по всей цепочке областей видимости — и всё равно останавливается на импортах
из другого модуля, если не собирает граф модулей целиком.

Циклы мы не считаем, а гасим. Разница видна на `for (let i = 0; i < 3; i += 1)`: там
значения `i` перечислимы, и Closure Compiler такой цикл развернёт. Для этого нужен
фикспоинт с ограничением на число итераций, и это следующий шаг после этой лабы.

## Куда это ведёт дальше

Свёртка констант — первое, что делает любой оптимизатор, и последнее, о чём вспоминают,
когда программа ведёт себя не так, как написано. На ней стоят
[минификация и tree shaking](../../../07-bundlers) (выбросить ветку под `if (!DEBUG)`
можно, только вычислив условие), сужение типов в [TypeScript](../../../05-typescript) —
та же решётка, только вместо значений типы, — и оптимизации в TurboFan
([раздел 11](../../../11-optimization-and-deopt)), где к этому добавляется обратная
связь по типам из рантайма и потому известно больше, чем видно в тексте.
