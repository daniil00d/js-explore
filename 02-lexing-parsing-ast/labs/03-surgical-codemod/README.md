# Лаба 02-3. Аккуратный кодмод

**Сложность:** средняя. **Что тренируем:** позиции узлов и правку текста по дереву.

## Задача

Реализовать в [`codemod.mjs`](./codemod.mjs) функцию `rewrite(source)`: заменить
каждый вызов `console.log(...)` на `logger.debug(...)` и **не изменить в файле
больше ни одного байта**.

Что является целью:

```js
console.log('привет');            // да
console.log(console.log(value));  // да, оба
() => console.log('из стрелки')   // да
```

Что целью не является:

```js
console.error('другой метод');       // другое имя
myConsole.log('другой объект');      // другой объект
console['log']('вычисляемый ключ');  // не тот вид обращения
globalThis.console.log('через это'); // object это не Identifier console
const call = console.log;            // ссылка, а не вызов
// упоминание console.log в комментарии
"строка с текстом console.log(x)"
```

Ограничение про «ни одного байта» — не придирка, а суть упражнения. Именно так
работают настоящие кодмоды: правка идёт по позициям узлов в исходном тексте,
а не перегенерацией файла из дерева. Иначе в диффе окажется весь файл — с
переставленными кавычками, съеденными висячими запятыми и переформатированными
переносами. Почему генерация кода не бывает обратимой, показано
в [`../../examples/walk-and-transform.mjs`](../../examples/walk-and-transform.mjs).

## Как проверить

```bash
node 02-lexing-parsing-ast/labs/03-surgical-codemod/check.mjs
```

Файла с ожидаемым результатом здесь нет — вместо него четыре свойства, которые
проверяются на каждой фикстуре:

1. результат остаётся корректным JavaScript;
2. все вызовы `console.log` заменены на `logger.debug` (и целей не осталось);
3. упоминания `console.log` вне вызовов сохранились — столько же, сколько было;
4. если в результате заменить `logger.debug` обратно на `console.log`, получится
   исходный файл байт в байт.

Третье свойство отсекает замену по тексту (она задевает комментарии и строки),
четвёртое — перегенерацию из дерева. Обе попытки честно проваливаются, это можно
проверить самому.

Фикстуры стоит прочитать: [`fixtures/app.mjs`](./fixtures/app.mjs) — обычный код
с похожими на цель местами, [`fixtures/edge.mjs`](./fixtures/edge.mjs) —
вложенные вызовы, инструкция без блока и ссылка без вызова.

## Если застрял

<details>
<summary>Как отличить цель от похожего места</summary>

У `console.log(x)` узел `CallExpression`, у него `callee` типа `MemberExpression`,
где `object` — `Identifier` с именем `console`, `property` — `Identifier` с именем
`log`, и `computed === false`. Каждое из этих условий отсекает один из случаев
в списке «не цель».
</details>

<details>
<summary>Какой диапазон заменять</summary>

Не весь вызов, а только `callee`: от `node.callee.start` до `node.callee.end`.
Аргументы вместе с комментариями внутри них и висячими запятыми останутся теми
же символами, что и были.
</details>

<details>
<summary>Почему правки не применяются по порядку</summary>

`logger.debug` на один символ длиннее `console.log`. Как только первая замена
выполнена, все позиции правее неё сдвинулись, а дерево про это не знает. Поэтому
правки применяют либо справа налево, либо собирая результат из кусков исходной
строки за один проход.
</details>

## Критерий готовности

`8 из 8`.

## Куда это ведёт дальше

Тот же приём — правка текста по позициям вместо перегенерации — лежит в основе
`magic-string`, которым пользуются Rollup и Vite: там так же важно не потерять
исходные байты, потому что из них потом собирается source map. Об этом
[раздел 06](../../../06-transpilers) и [раздел 07](../../../07-bundlers).
