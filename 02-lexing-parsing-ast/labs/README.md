# Лабы раздела 02

Три задачи по всей длине конвейера: текст → токены → дерево → снова текст.

| Лаба | Задача | Проверок |
| --- | --- | --- |
| [01-finish-the-lexer](./01-finish-the-lexer) | Дописать лексер: числа, приватные имена, «регулярка или деление» | 19 |
| [02-write-a-lint-rule](./02-write-a-lint-rule) | Написать правило линтера `no-await-in-loop` на AST | 5 |
| [03-surgical-codemod](./03-surgical-codemod) | Переписать вызовы, не изменив в файле ни одного лишнего байта | 8 |

Каждая упирается в отдельную идею раздела: первая — что независимого лексера
в JavaScript не существует, вторая — что статический анализ рассуждает о форме
дерева, а не о тексте, третья — что дерево не помнит форматирование, и поэтому
правки делают по позициям.

## Как это работает

```bash
npm install    # лабам нужны acorn и acorn-walk

node 02-lexing-parsing-ast/labs/01-finish-the-lexer/check.mjs
node 02-lexing-parsing-ast/labs/01-finish-the-lexer/check.mjs --solution
node tools/labs.mjs
```

Эталон для проверок берётся не из файла с ответами:

- в лабе про лексер поток токенов сверяется с настоящим лексером `acorn`;
- в лабе про линтер ожидаемые места разметки помечены в самих фикстурах
  комментарием `// линтер`;
- в лабе про кодмод проверяются свойства правки — в том числе то, что обратная
  замена даёт исходный файл байт в байт.
